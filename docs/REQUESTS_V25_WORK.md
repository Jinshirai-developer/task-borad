# v25: お助け依頼の導線と文言

2026-09-09。お助けタスクを見つけにくい、モーダルの行き来が多い、文言が不自然という指摘への対応。

## 操作の変更

- 上部の「依頼」を「お助け依頼」に統一。一覧は通常のページ内に表示し、モーダルを使わない。
- 「届いた依頼」「対応中」「送った依頼」を切り替える。引き受けたお助け依頼は対応中に残り、自分が送った依頼は送った依頼から解決・取り下げできる。
- 一覧に依頼の種類・チーム・本文・依頼者と宛先・状況を表示。確認・引き継ぎでは完了条件も表示する。質問返却時は、質問を送った人から元の依頼者への向きで表示。
- 引き受け、対応辞退、解決、取り下げ、確認受領を一覧上で実行。タスクの担当変更を伴う場合は「担当を引き継ぐ」と明示する。
- 「詳細・メモ」だけが詳細モーダルを開く。元のワークスペースを切り替えずに別チームの依頼を表示し、「お助け依頼に戻る」で元の一覧・表示条件へ戻れる。
- チームのカードに「お助けを依頼」を追加。メモを開いてからタブを探す必要がない。送信は既存のフォームを使用する。
- 詳細モーダルの自分用メモ・旧作品機能を下部へ移し、依頼の本文と操作を先に表示。
- 依頼一覧は全チームが対象のため、ワークスペース別のタグフィルターは一覧表示中に隠す。

## 実装と整合性

`GET /api/work-inbox?view=incoming|helping|sent`。省略時は従来どおりincoming。閲覧者に関連する未完了の依頼だけを返す。`DirectCount` / `TeamCount` は届いた依頼の件数を維持し、`HelpingCount` / `SentCount` を追加。

一覧には現在の依頼状態に対応する操作、タスクのVersionとUpdatedAtを含める。ボタンは表示時のVersionを既存の認可・競合検出付き更新APIへ送る。最新Versionを取り直して無条件に実行しない。409では処理を自動再送せず、最新内容を表示して再操作を案内する。

表示切替後に到着した古い応答を無視。定期読み込み中でも一覧操作を受け付け、古い読み込みが操作結果を上書きしないようにする。保存中は二重送信を防ぐ。通信失敗で古い依頼本文を表示し続けず、0件とも扱わない。

本人用メモは一覧レスポンスに含めない。各APIで所属・当事者権限を検証。DBスキーマと報酬仕様は変更なし。デモは同じ一覧・操作契約をブラウザ内で再現する。
