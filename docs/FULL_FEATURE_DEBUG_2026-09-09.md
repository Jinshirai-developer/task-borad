## 見つけて修正した検証上の問題

1. **progression／collectionの期待値が古い。** 基本の種類・テーマ・レイアウトがレベルでロックされる、完了取消で獲得済み装備が使えなくなる、という旧仕様が残っていた。現在の仕様に合わせ、Lv.1からの基本設定、経験値の不正指定が反映されないこと、取消後も獲得済みの装備と成長姿を保持することを検証するよう修正した。並行完了・取消・他ユーザー分離の検証は維持した。
2. **複数スモークを連続実行すると、テストクライアントのIP再利用で429が混入する。** 新しい一括実行スクリプトでクライアントを先に起動し、すべての検証が終わるまでIPを保持した。アプリのレート制限は無効化していない。
3. **billingスモークの確認メールoriginが単一ポート固定。** 従来の専用ポート5117に加えて、今回の隔離環境5100だけを許可した。任意の外部URLは受け付けない。

修正対象はテストと記録。今回、アプリ本体の挙動を変更する修正や追加デプロイは行っていない。

## 再実行

Dockerと `task-board:requests-v25` が必要。検証環境はアプリの既存スキーマだけを利用し、ユーザーデータ・認証鍵・Stripe認証情報はコピーしない。5100／8100番ポートと検証用コンテナ名が空いている状態で実行する。

```sh
python3 tests/request-fixture.py start
python3 tests/full-feature-check.py
python3 tests/request-fixture.py stop
```

一部だけなら `python3 tests/full-feature-check.py teams requests`。失敗時にもログを確認してから `stop` で専用環境を片付ける。一括実行スクリプトは対象コンテナのラベルと内部ネットワークを検査し、既存プレビューには接続しない。スイートごとのアカウント削除に加え、fixtureの停止で専用DBを破棄する。

実画面のA／Bも専用DB内の検証ユーザーであり、普段使っているSafari／Chromeのログインには触れていない。

検証終了後、専用のブラウザウインドウを閉じ、`request-fixture.py stop` の成功を確認した。専用アプリ・DB・Mailpit・プロキシ・ネットワークは削除済み。通常の5097番プレビューと既存契約は維持した。最後のテスト整理後もPython／JavaScriptの構文検査と `git diff --check` は成功した。
