# 公開URLを用意する具体案

2026-09-09時点。公開先の契約・アップロード・DNS変更はまだ行っていません。

## 推奨する進め方

採用担当が登録なしで触れるデモURLを先に用意し、その後、バックエンドの実装を見せる通常版を公開する流れを推奨します。

| 方法 | 見せられるもの | 必要なもの |
| --- | --- | --- |
| 登録不要の静的デモ | タスク操作・相棒・検索・疑似チーム/SOS。再読み込みでリセット | 公開用デモファイル、静的ホスティングのアカウント |
| 認証・DB込みの通常版 | 実際の登録、保存、別利用者とのチーム共有、メール確認 | Docker実行基盤、PostgreSQL、永続鍵ストレージ、SMTP、運営情報 |

デモの疑似APIはすでに実装済みです。静的公開だけではサーバー側の認証・DB保存・同時更新を実証できないため、ポートフォリオではその範囲を明記します。

## A. 登録不要デモを公開する

候補はCloudflare Pages。ローカルで用意したフォルダまたはZIPをDirect Uploadで配信し、`<project>.pages.dev` のURLを取得できます。公開・更新の手順は[公式ガイド](https://developers.cloudflare.com/pages/get-started/direct-upload/)にあります。無料枠と上限は[公式料金案内](https://pages.cloudflare.com/)で確認します。独自ドメインは必須ではありません。

残りの実装・作業:

1. **公開用のデモ出力を作る。** 実行に必要なHTML・CSS・JS・配信画像だけを出力し、リポジトリ全体や `.local`・設定ファイルを配信対象にしない。
2. **入口を常にデモにする。** 現在の `/index.html` は通常版で、`?demo=1` がある場合だけデモになる。ルートからも必ずデモとして初期化し、APIを呼ばないことを確認する。現状の `frontend` を丸ごとアップロードするだけでは完了しない。
3. **通常版への導線を整理する。** ログイン・登録・メール再設定・利用情報の表示を静的デモ向けに合わせる。「ブラウザ内の一時データ」「実共有・実請求なし」を表示する。
4. Cloudflareのアカウントでプロジェクトを作り、確認済みの公開用フォルダをアップロード。継続的な自動更新が必要なら初めからGit連携を選ぶ。Direct Uploadの既存プロジェクトは後からGit連携へ切り替えできない。
5. 発行URLを別端末・未ログインで開き、入口、画像、操作、リセット、スマホ表示、リンクを確認。READMEのlocalhostリンクを公開URLへ置き換える。

この方法ではPostgreSQLやSMTPを公開用に契約する必要はありません。現時点では専用の静的出力と公開は未実装です。

## B. 通常版を公開する

候補構成は、Renderの有料Web Service（Docker）＋有料PostgreSQL＋永続Disk＋外部SMTPです。現在の.NET 10用Dockerfileを使う方針が取れます。[RenderはDockerfileからのビルドと実行をサポート](https://render.com/docs/docker)しています。

Render無料Web Serviceは永続Diskを付けられず、一般的なSMTPポートも制限されます。無料PostgreSQLは作成から30日で期限切れになります。現在の実装のまま継続公開する構成としては、有料リソースが適しています。費用はWeb・DB・Disk・メール・必要ならドメインを合計して決定します。[無料枠の制限](https://render.com/docs/free)

実施順:

1. 公開先アカウント、月額上限、送信元メール/ドメイン、運営者名・問い合わせ先を決める。
2. 公開用DBを作成。手元の利用者データやStripe設定は自動コピーせず、新規環境として開始する。
3. リポジトリの必要ファイルをコミットし、CI合格した版をDockerでビルド。実行ポート8080を基盤に設定する。
4. [.env.example](../.env.example)に沿って環境変数・Secretを設定。`Production`、公開ホスト、HTTPSの`Authentication__PublicBaseUrl`、DB、SMTP、Legal設定を埋める。初回は`Billing__Enabled=false`を推奨。
5. 永続Disk内に`Authentication__KeyRingPath`を置く。Docker実行ユーザー1654が読み書きできることを確認し、再デプロイでも鍵が消えないようにする。
6. .NET 10 SDK/EFの専用ジョブでMigrationを適用。現在のランタイムイメージはEF CLIを含まず、起動時の自動Migrationも行わないため、別のリリース処理を用意する。
7. HTTPSと転送ヘッダー、readiness `/health/ready`、実メール、異なる利用者同士の権限・共有、再起動後の保存・ログインを公開URLで確認する。
8. DBと鍵のバックアップ・復元を確認し、READMEに通常版と登録不要デモのURLを載せる。

環境変数の詳細、メール配送、プロキシ、バックアップ、公開URLでの確認項目は既存の[DEPLOYMENT.md](DEPLOYMENT.md)を利用します。ホスティング契約前に料金とSMTP到達性を選択プランで確認し、公開環境で未確認の設定を確定済みとして扱わないでください。
